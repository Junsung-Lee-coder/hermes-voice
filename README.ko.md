# Hermes Voice

**Android 폰과 Wear OS 워치에서 음성이나 텍스트로 Hermes 대시보드와 대화하세요.**

Hermes Voice는 Wear OS 보조 앱이 함께 제공되는 실험적인 Android 앱입니다. 폰 앱은 호환되는 [Hermes](#동작-방식) 대시보드에 로그인하고, 앱에서 만든 대화를 관리합니다. 워치 앱은 워치에서 직접 녹음하고, 대화를 읽고, 답변을 재생합니다. 워치의 요청은 짝지어진 폰이 Hermes로 전달하며, 워치는 Hermes에 직접 연결하지 않습니다.

## 주요 기능

- **텍스트 채팅**: 첨부 파일(메시지당 최대 6개, 각 10 MiB)과 페이지 단위 대화 기록을 지원합니다.
- **수동 음성**: 폰에서는 버튼을 눌러, 워치에서는 1초 동안 길게 눌러 녹음 상태를 전환합니다. 음성 인식과 음성 합성에는 대시보드에 설정된 음성 서비스를 사용합니다.
- **음성 라우팅**(기본 켜짐, 끌 수 있음): 말로 한 요청을 음성 별칭으로 대화 중 하나에 전달하며, 라우터가 새 대화를 제안할 수도 있습니다. 라우팅을 끄면 요청을 보낸 기기에서 선택한 대화로 전달됩니다.
- **핸즈프리(선택 기능)**: 호출어, 백그라운드 듣기, 나중 답변을 쓸 수 있으며 모두 기본으로 꺼져 있습니다.
- **두 기기의 설정**: 화면 모드, 음성으로 읽어 줄 답변의 범위가 있습니다. 호출어와 워치 관련 옵션은 폰에서 설정하면 워치에 동기화됩니다.
- **개인용 헤드셋 출력**과 헤드셋 녹음 제어(기본 꺼짐). [헤드셋 모드](#헤드셋-모드)를 참고하세요.

## 동작 방식

```text
Watch  ──Wear Data Layer──▶  Phone  ──HTTPS / WebSocket──▶  Hermes dashboard
(녹음, 재생, 대화 읽기)         (로그인, 대화,                   (STT, TTS, 세션)
                              음성 라우팅)
```

- 폰이 대시보드에 인증하고 대시보드 API를 직접 호출합니다. 각 대화는 앱이 만든 대시보드 세션이며, 폰의 로컬 등록부에 있는 세션만 목록에 표시됩니다.
- 워치는 짝지어진 폰과만 메시지를 주고받으며, 폰이 워치의 요청을 Hermes로 전달합니다. 대시보드 자격 증명은 워치에 저장하지 않고, 워치가 Hermes에 직접 연결하지도 않습니다.
- 음성 인식과 합성은 대시보드에 설정된 STT와 TTS를 사용합니다. 해당 서비스를 사용할 수 없거나 설정이 잘못되어 있으면 음성 요청이 실패할 수 있습니다.

## 시작하기

1. 폰과 워치 빌드를 설치합니다. 두 앱은 애플리케이션 ID(`com.rumi.hermesvoice`)와 서명 키가 **모두** 같아야 하며, 그렇지 않으면 Data Layer가 둘 사이에서 전달되지 않습니다. [빌드와 테스트](#빌드와-테스트)를 참고하세요.
2. 폰에서 **Settings**를 열고 대시보드 URL을 입력합니다. 예: `https://hermes.example.com/`. Hermes 프로필도 입력할 수 있습니다.
   - HTTPS를 사용하세요. 일반 HTTP는 루프백 또는 Tailscale(`100.64.0.0/10`) 주소에서만 허용됩니다. 자격 증명이 포함된 URL은 거부됩니다.
3. **Sign in**을 누릅니다. 시스템 브라우저에 대시보드의 로그인 페이지가 열립니다(PKCE를 사용하는 네이티브 앱 방식). 대시보드가 이 방식을 지원해야 합니다. 앱은 비밀번호를 볼 수 없으며, 비밀번호나 API 키를 앱에 내장하지 않습니다.
4. 대화를 만들고 음성 별칭을 지정합니다(소문자, 숫자, `-`, `_`, 최대 32자). 음성 요청은 이 별칭으로만 전달됩니다.
5. 폰에서는 **Talk**를 눌러 녹음을 시작하고, 다시 눌러(**Stop & send**) 전송합니다. 워치에서는 메인 화면의 아무 곳이나 움직이지 않고 1초 동안 길게 눌러 녹음을 시작하고, 같은 동작을 다시 하면 녹음을 멈추고 전송합니다. 누르고 있는 동안만 녹음하는 방식이 아니라 전환 방식이므로, 손을 떼어도 녹음이 멈추지 않습니다.

로그인 토큰은 Android Keystore 키로 보관하며, 백업과 기기 이전에서 제외되고, 하나의 대시보드 URL과 프로필에 묶입니다.

## 음성과 워치

- **음성 요청의 흐름.** 녹음에 쓸 만한 오디오가 있는지 확인하고 대시보드에서 텍스트로 변환합니다. 라우팅이 켜져 있으면 텍스트를 숨겨진 라우팅 세션으로 보내 별칭에 맞는 대화를 고르며, 라우터는 엄격한 JSON 객체로만 응답해야 합니다(다른 형식은 거부됩니다). 라우팅이 꺼져 있으면 요청을 보낸 기기에서 선택한 대화로 전달하고, 선택한 대화가 없으면 요청을 거부합니다. 어느 쪽이든 짧은 음성 확인 안내가 재생된 뒤에 해당 대화로 전달됩니다.
- **답변이 재생되는 곳.** 기본적으로 가장 최근에 수락된 음성 요청을 보낸 기기에서 재생됩니다. 그 기기가 워치인데 연결할 수 없으면 폰에서 대신 재생하지 않습니다. 예외는 폰의 [헤드셋 모드](#헤드셋-모드)이며, 이때는 음성 답변이 헤드셋으로 재생됩니다.
- **워치 리더.** 워치는 앱이 소유한 대화를 보여 줍니다. 왼쪽으로 밀면 목록과 열린 대화 사이를 전환하고, 오른쪽으로 밀거나 뒤로 가기를 누르면 앱이 백그라운드로 이동합니다. 대화당 최대 200개의 메시지만 보관하며, 더 오래된 메시지는 폰에서 볼 수 있습니다.
- **호출어**(기본 꺼짐, 폰에서 설정). **Listen on**에서 Off, Watch, Phone, Both 중 하나를 고릅니다. 호출어 목록은 두 기기가 공유합니다. 기본적으로 해당 기기의 앱이 열려 있는 동안에만 듣습니다.
- **백그라운드 사용**(모두 기본 꺼짐). 폰은 앱을 닫거나 화면을 꺼도 계속 들을 수 있고, 워치는 백그라운드 세션을 유지할 수 있습니다. 기기 내 음성 인식기가 필요하고, **Stop**이 있는 알림이 표시되며, 열려 있는 앱에서만 시작할 수 있습니다.

## 헤드셋 모드

**Use headset**은 폰의 Settings에 있으며 **기본으로 꺼져 있습니다**. 켜져 있고 개인용 오디오 출력(유선, USB, 블루투스 헤드폰 또는 헤드셋)이 폰에 현재 연결되어 있을 때 적용됩니다. Android가 일부 블루투스 헤드셋과 스피커·차량 오디오를 확실히 구분하지 못할 수 있으므로, 개인용 헤드셋에서만 켜세요. 이어버드는 먼저 착용하고 연결 상태를 확인하세요. 앱이 착용 여부를 확인하지는 않습니다.

적용되는 동안의 동작은 다음과 같습니다.

- **답변이 폰에서 개인적으로 재생됩니다.** 모든 음성 답변은 그 헤드셋으로만 나갑니다. 폰이나 워치에서 말한 요청의 답변, 나중 답변, 직접 입력한 메시지의 답변이 모두 해당합니다. 워치 스피커와 폰 스피커에서는 재생되지 않으며, 워치에는 소리를 내지 않도록 요청합니다. 헤드셋 연결이 끊기면 답변은 멈추고 스피커로 옮겨 재생되지 않습니다. 답변 텍스트는 그대로 볼 수 있으며, 알림은 Android 설정에 따라 표시됩니다. 이 모드가 대화를 지켜보는 시간을 늘리지는 않습니다.
- **헤드셋 버튼.** 수락된 **PLAY** 또는 **PAUSE**는 폰의 현재 녹음 상태를 전환합니다. 대기 상태이면 녹음을 시작하고, 녹음 중이면 멈춥니다. 한 번의 누름이 두 번 전달되어도 한 번으로 처리합니다.
- **알림음.** 녹음을 시작하면 개인용 알림음이 한 번, 멈추면 두 번 울립니다. 이 소리는 헤드셋으로만 재생되며 녹음되는 요청에는 포함되지 않습니다.
- **워치 녹음은 독립적으로 계속됩니다.** 워치는 자체 요청을 녹음하고 전송할 수 있으며, 폰의 헤드셋 모드를 켜도 이 기능은 꺼지지 않습니다. 그 답변은 헤드셋으로 재생됩니다.

주의: 화면이 꺼져 있거나 앱이 백그라운드에 있을 때 버튼이 동작하는지는 Android가 마이크 포그라운드 서비스를 허용하는지와 기기의 전원 정책에 달려 있으며, 다른 미디어 앱이 미디어 버튼을 가져갈 수도 있습니다. 블루투스 출력이 연결되어 있다고 해서 그 마이크로 녹음된다는 뜻은 아닙니다. 특정 헤드셋 모델은 보장하지 않습니다.

## 빌드와 테스트

| 항목 | 버전 |
| --- | --- |
| JDK | 17 |
| Kotlin | 1.9.22 |
| Android Gradle Plugin | 8.13.2 |
| Gradle | 8.13, 별도 설치 (**Gradle wrapper 없음**) |
| Android SDK | Platform 35 (`compileSdk`, `targetSdk` 35) |
| `minSdk` | 폰 29, 워치 30 |

`ANDROID_HOME` 환경 변수 또는 `sdk.dir=...`이 들어 있는, 추적하지 않는 `local.properties` 파일로 Gradle이 Android SDK를 찾게 합니다. 그런 다음 디버그 APK 두 개를 빌드합니다.

```sh
gradle --no-daemon :phone:assembleDebug :watch:assembleDebug
```

두 APK 모두 로컬 디버그 키스토어로 서명됩니다. 워치 연결이 동작하려면 같은 키스토어를 사용해야 합니다. 의존성은 Google Maven과 Maven Central에서 받습니다.

순수 JVM으로 동작하는 core 테스트는 Gradle로 실행합니다.

```sh
gradle :core:test
```

Gradle이나 Android SDK 없이 `scripts/core-jvm-check.sh`로도 실행할 수 있습니다. 이 스크립트는 `java`, `curl`, `python3`, `sha256sum`이 필요하며, 사용하는 모든 jar를 SHA-256으로 검증합니다. 검사 대상은 `:core`뿐입니다.

```sh
# First run: FETCH=1 downloads kotlinc 1.9.22 and the pinned jars into the tools directory.
HERMES_VOICE_TOOLS="$HOME/.cache/hermes-voice-tools" FETCH=1 scripts/core-jvm-check.sh

# Later runs reuse the tools directory. Optional environment variables:
#   HERMES_VOICE_WORK=<dir>  build output directory (default: a new temporary directory)
#   TMPDIR=<dir>             temporary directory for the compiler and JVM
#   COMPILE_ONLY=1           compile the core without running the tests
HERMES_VOICE_TOOLS="$HOME/.cache/hermes-voice-tools" scripts/core-jvm-check.sh
```

폰과 워치의 UI 테스트는 Robolectric으로 실행되며 추가 테스트 의존성이 필요합니다. [android-test-harness/README.md](android-test-harness/README.md)를 참고하세요. [`verification/`](verification) 디렉터리에는 이전 스냅샷의 소스 매니페스트와 테스트 오버레이 패치가 있습니다.

## 저장소 구조

| 경로 | 내용 |
| --- | --- |
| `core/` | 순수 Kotlin/JVM 라이브러리와 그 테스트: 로그인, 대시보드 클라이언트, 세션, 채팅, 음성 처리, 설정, 폰↔워치 규약 |
| `phone/` | Android 앱(Jetpack Compose): 로그인, 대화, 채팅, 음성, 설정, 헤드셋 제어, 워치 연결. 자체 Android 테스트 포함 |
| `watch/` | Wear OS 앱(Compose for Wear OS): 대화 리더, 음성, 선택 기능인 호출어, 재생. 자체 Android 테스트 포함 |
| `scripts/` | Gradle 없이 core를 검사하는 `core-jvm-check.sh` |
| `android-test-harness/` | Robolectric 테스트용 테스트 전용 Gradle 추가 설정 |

| `docs/assets/` | README용 이미지 |

## 나중 답변

<details>
<summary>선택 기능인 나중 답변이 재생되는 방식</summary>

**Speak later replies**는 기본으로 꺼져 있습니다. 이 폰에서 직접 켜야 하는 동의 설정이며, 복원하거나 새 폰으로 옮긴 설치본은 꺼진 상태로 시작합니다. 켜면 요청이 전달된 뒤 일정 시간 동안 해당 대화를 지켜보다가, 그 시간 안에 도착하는 어시스턴트의 후속 답변을 하나씩 음성으로 읽어 줍니다. 지켜보는 시간은 **Follow for**에서 1분부터 3일까지 정할 수 있으며 기본값은 30분입니다.

- **순서와 한도.** 나중 답변은 도착한 순서대로 한 번에 하나씩 준비하거나 재생합니다. 지켜보는 요청 하나당 준비 중이거나 재생 중인 하나와 대기 4개를 허용하며, 전체로는 최대 8개입니다. 이를 넘으면 재생되지 않은 것으로 보고합니다.
- **재생되는 곳.** 가장 최근에 수락된 음성 요청의 기기에서 재생되며, [헤드셋 모드](#헤드셋-모드)가 적용되면 헤드셋으로 재생됩니다. 음성 요청이 진행 중이거나 재생될 기기에서 녹음 중이면 기다립니다. 다른 기기는 기다리지 **않습니다**. 폰이 녹음하는 동안 워치에서 답변이 재생될 수도 있고, 그 반대도 가능합니다.
- **시작 제한.** 답변은 도착한 뒤 **10분 안에만 재생을 시작할 수 있습니다**. 스피커가 비어 있고 재생될 기기의 마이크가 사용 중이 아닐 때 시작할 수 있으며, 시작하지 못하면 재생되지 않은 것으로 보고합니다.
- **전체 시간 제한 없음.** 일단 시작한 답변은 전체 시간 때문에 **중간에 끊기지 않습니다**. 긴 답변은 여러 조각으로 나누어 차례로 합성하고 재생합니다. 실패, 연결 끊김, Stop, 옵션 끄기가 있을 때만 끝납니다.
- **전력.** 한 조각을 읽어 주는 단위마다 Android에 CPU를 켜 두도록 요청하며, 그 시간은 최대 7분 5초이고 조각마다 새로 시작됩니다. 단위가 끝나면 바로 해제합니다. 서버가 한 조각의 음성을 만드는 동안에는 CPU, 마이크, 오디오 포커스를 붙잡지 않습니다.
- **놓치는 경우.** 지켜보는 시간이 지난 뒤에 도착한 답변은 읽어 주지 않습니다. 대시보드 연결이 끊기면 그 뒤의 출력은 놓칩니다. Android가 폰 앱 프로세스를 종료하면 대기 중이던 답변은 모두 사라집니다. Hermes는 답변이 어느 요청에 속하는지 표시하지 않기 때문에, 다른 Hermes 클라이언트에서 같은 대화로 보낸 내용에 대한 답변도 읽어 줄 수 있습니다.
- **멈추는 경우.** 그 대화에 새 메시지를 보내면 지켜보기가 끝납니다. 옵션을 끄거나 백그라운드 릴레이 또는 백그라운드 듣기의 Stop을 누르면 모든 지켜보기와 대기 중인 모든 답변이 끝납니다.

</details>

## 알려진 제한 사항

- 개발(디버그) 빌드입니다. 릴리스 서명과 코드 축소는 설정되어 있지 않습니다.
- 워치에는 이 앱이 실행되는 짝지어진 폰이 필요합니다. Wear Data Layer를 쓰려면 두 기기 모두에 Google Play 서비스가 필요합니다.
- 호출어 듣기는 각 기기의 플랫폼 음성 인식기를 구간마다 반복해서 사용합니다. 저전력 전용 호출어 엔진이 아닙니다. Android가 백그라운드 듣기를 중단할 수 있으며, 배터리 사용량은 측정하지 않았습니다.
- 백그라운드 녹음과 듣기는 앱이 포그라운드에서 시작해야 하며, 강제 종료, 권한 변경, 기기 재시작 뒤에는 중단됩니다.
- 녹음의 핸즈프리 종료는 말을 이해하는 것이 아니라 소리 크기를 기준으로 합니다.
- 답변은 순서로 요청과 연결됩니다. 게이트웨이가 요청별 ID를 보내지 않습니다.
- 도구 승인과 같은 Hermes 서버 측 요청에는 응답하지 않습니다.
- 화면 꺼짐, Doze, 실제 헤드셋 하드웨어, 배터리 소모와 같은 실제 기기 동작은 모든 기기에서 확인하지 않았습니다.
